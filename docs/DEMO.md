# Демонстрация 8 ноября

## Подготовка

1. Запустить `start.cmd`, дождаться готовности. При первой сборке потребуется интернет. На защите лучше использовать уже собранные образы.
2. Открыть http://127.0.0.1:8050.
3. Если нужны заранее готовые модели всех трёх датчиков, запустить `demo.cmd`. Он проверяет все сценарии через сервисы.

## Показ за 5–7 минут

**Задача, около 30 секунд.** «Система помогает исследовать температурные показания климатического оборудования: загрузить измерения, обучить модель нормального поведения, найти отклонения и получить отчёт. Предметная область связана с моей исследовательской работой».

**Архитектура, около минуты.** Открыть «Состояние системы» и показать пять работающих сервисов. Объяснить: каждый в своём контейнере, SQLite доступна только Storage, модель обучается в ML Service, пользовательские сценарии организует Web Master, интерфейс — отдельный сервис. При необходимости показать `docker compose ps` и `/docs` одного сервиса.

**Сценарий 1 — загрузка.** Открыть «Данные». Показать три датчика, диапазон, число записей и пропуски. Показать форму своего CSV или загрузить демонстрационный набор. Для выдачи ровно одного следующего пакета доступна кнопка «Следующий пакет». Полная загрузка состоит из последовательных запросов Collector.

**Сценарий 2 — обучение.** На обзоре выбрать датчик и открыть «Обучить новую модель». Объяснить границы обучения и калибровки. Запустить обучение; показать прогресс. Для быстрой демонстрации можно выбрать 5 эпох: это покажет работоспособность API, а заранее обученная 120-эпоховая версия останется доступной для анализа. Качество короткого запуска не следует представлять как лучший исследовательский результат.

**Сценарий 3 — анализ.** Выбрать готовую модель и период после калибровки. Нажать «Найти аномалии». Показать масштабирование графика, измерения, реконструкцию, красные срабатывания, фон разметки и отдельную кривую score с порогом.

**Сценарий 4 — оценка и отчёт.** Показать precision/recall/F1. Объяснить, что срабатывания считаются по точкам и метрики доступны только при наличии разметки. Скачать и открыть HTML-отчёт; показать CSV.

**История и сохранение.** Открыть «История запусков», выбрать предыдущий результат. Объяснить сохранение данных и моделей в томах. При достаточном времени перезапустить контейнеры и показать тот же запуск.

## Что важно уметь объяснить

- API — способ взаимодействия независимых программ по HTTP.
- Контейнер — отдельная среда запуска сервиса; Compose управляет всей системой.
- Автоэнкодер восстанавливает прошлое окно; большая ошибка последней точки даёт сигнал аномалии.
- Порог настроен на отдельном прошлом периоде. Тестовые значения не участвуют в обучении и выборе порога.
- Временная отметка агрегата — конец интервала, поэтому в ней нет ещё не полученных измерений.
- Без разметки можно получить срабатывания, но нельзя честно вычислить качество относительно истинных аномалий.
- Демонстрационные периоды ранее использовались в исследовании; результаты не являются внешней независимой проверкой.
